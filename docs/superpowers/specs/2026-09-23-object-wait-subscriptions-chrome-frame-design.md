# 对象等待精确唤醒与 Chrome 窗口关闭按钮设计

状态：待用户审阅；本文件是设计规格，不代表已修改或验证产品代码。

## 目标

解决 LiteOS 桌面和 Chrome 交互卡顿，并让来宾系统实际打开、显示在线 HTTPS 页面；修复 Chrome 应用窗口的关闭按钮，使其图标可见、命中区域正确且鼠标点击确实关闭窗口。现有可见 QEMU 必须保持运行，集成验证只在独立克隆镜像中进行。

## 当前证据

- `kernel/object/object.c` 将 `object_wait_many()` 和 `object_wait_on_signal()` 的等待者放在同一个 `g_object_signal_queue` 上。任何对象调用 `object_notify_signaled()` 都对这条全局队列执行 `wake_all()`。已有运行时 GDB 采样捕获到通知路径触发 `x86_smp_request_reschedule`；此前计数约为每秒十万次 reschedule IPI。源码与运行时证据共同指向跨对象广播唤醒，但修改后的效果仍需测量。
- Linux `eventfd` 和 `epoll` 使用对象通知路径。`epoll_wait` 依赖自定义 readiness predicate 和每个 watch 的事件掩码；不能用“任一被监视对象 `is_signaled`”替代该谓词。
- Chromium 的 `OpaqueBrowserFrameView` 在创建关闭按钮时传入 `HTMAXBUTTON`，而 `NonClientHitTest()` 对关闭按钮返回 `HTCLOSE`。这证明标记不一致，但尚未证明它是叉号不可见的原因。现有回归覆盖不足以验证实际 frame 绘制或真实鼠标点击关闭。
- 当前导航日志曾多次记录 `AFTER_BEFORE_UNLOAD_CHECK`，但缺少 before-unload 回调/ACK 的成对日志；尚不能据此断定在线导航卡在 renderer、TCP 或 TLS。网络连接实现存在可疑路径，但在到达外部 TCP 前不先行改写。

## 设计

### 1. 对象级等待订阅

为每个内核对象提供与对象生命周期绑定的 signal wait queue（首选嵌入 `object_header_t`，或采用同等安全的生命周期绑定方案）。每个对象构造器必须在对象对其他线程可见之前初始化该队列。移除 `g_object_signal_queue` 作为对象通知的公共等待点；通知只触达被通知对象的订阅者，不再唤醒等待无关对象的线程。为同一对象订阅的等待者仍需按其 wait 语义重新检查条件，不能把一次通知当作条件必然成立。

等待一个对象沿用单队列路径。`wait_any`、`wait_all` 和自定义 predicate 等待使用一个逻辑 wait-set，并为集合内每条对象队列分别登记 subscription node；共享一个等待状态、一个超时登记和一个线程。不要在有限内核栈上按最大句柄数分配大型订阅数组；订阅容量需校验，并使用合适的内核分配/可失败路径。

多队列登记、条件复查、唤醒、超时和取消必须共同防止丢唤醒及悬空链表节点。保留现有队列序列号机制的用途：登记前采样各队列序列，条件检查并登记后比较序列；若任何序列变化则撤销全部登记并重新检查。wait-set 进入任一终态时，必须从所有对象队列及超时队列摘除全部节点后才允许等待调用返回。

明确并统一锁顺序：先取得等待/超时状态锁，再按稳定顺序取得该 wait-set 涉及的队列锁；所有超时、通知、取消和清理路径遵守同一规则。对象状态生产者应在释放对象私有锁后发通知。保留对象引用直到所有订阅解除，避免等待期间对象释放或 epoll watch 删除造成 UAF。

`epoll_wait` 对当前 watch 集合中的源对象队列建立订阅，同时保留 epoll 控制变更的可唤醒路径；每次唤醒仍用原有的掩码感知 readiness predicate 扫描并返回事件。并发 `epoll_ctl` 更新必须唤醒同一 epoll 实例中等待的线程；睡眠期间持有被订阅对象的引用，重建 watch 快照时正确释放旧引用。对无需等待即可立即返回的 watch（例如当前实现中被视为立即就绪的普通文件）维持现有语义。

通知的扇出上限是“该对象的订阅者”，不是全系统对象等待者。对于同一对象是否唤醒一个还是全部订阅者，由现有对象及 wait-any/all 语义决定；不能为减少 IPI 而静默丢失合法等待者的进展。

### 2. 关闭按钮绘制、命中与点击

先添加能在真实浏览器 frame 上失败的回归测试，再修实现。测试应覆盖：

1. 在实际显示的应用窗口 frame 中捕获/绘制关闭按钮区域，确认关闭 glyph 有可见的前景像素；避免依赖脆弱的逐像素抗锯齿快照。
2. 关闭按钮中心点的 frame hit-test 结果为 `HTCLOSE`，最大化/还原/最小化按钮仍命中各自区域。
3. 对真实可见窗口的关闭按钮中心发送鼠标点击，并断言对应 `BrowserWidget` 被关闭，且关闭原因是 `kCloseButtonClicked`。

再统一创建语义与命中语义：关闭按钮构造标记应为 `HTCLOSE`。若绘制测试仍复现缺失叉号，沿实际 frame button style、图标资源、可见性/布局及 paint 路径定位并修复，不把更正标记当作绘制问题已解决的证据。Linux `kMdButton` 路径至少要被覆盖；其他构建变体使用的图标路径不得被回归破坏。

### 3. 在线网页端到端验证

在克隆镜像中增加/启用分阶段诊断，能区分导航的 before-unload dispatch/ACK、`BeginNavigation`、DNS、TCP SYN/握手、TLS、HTTP 响应和页面绘制。用来宾 Chrome 打开一个明确的 HTTPS 在线页面，并核对最终 URL、页面标题/正文标记和可见画面；同时检查桌面及窗口输入仍有响应。

按第一个未完成阶段定位后续缺陷。只有当跟踪证明连接路径实际到达外部 TCP，且确认 `connect` 的异步握手/返回语义导致停滞或错误时，才修改 `socket_connect` 并为该行为加回归；若卡在 before-unload、renderer 或 DNS，则继续修对应层，不以盲改 TCP 代替定位。

## 回归测试与验收

- 内核并发回归覆盖 `wait_any`、`wait_all`、永不满足条件的超时、通知与登记竞态、超时与通知竞态、取消/清理及对象引用生命周期。至少创建多个不同对象的等待者，通知其中一个对象时，其他对象的等待者不得被置为可运行；被通知对象的合法等待者必须最终重新检查条件并取得正确结果。
- 测试 `epoll` 的掩码筛选、多个 watch、并发 `epoll_ctl` 与 `epoll_wait`、超时，以及源对象关闭/删除竞态，确保没有漏事件、错误事件或悬空引用。
- 测量修复前后同一负载下的 reschedule IPI、无关线程唤醒数、QEMU/来宾 CPU 占用和输入/打开应用延迟。通知造成的唤醒数应随被通知对象的订阅者规模变化，而非全局对象等待者规模；不能仅凭“页面可打开”声称卡顿已修复。
- Chromium 回归验证 frame 像素、命中测试和真实点击关闭；增量构建 Chrome 及所需测试目标并运行定向测试。
- 构建 LiteOS 后将新内核/Chrome 放入独立克隆镜像启动图形 QEMU，完成在线 HTTPS 页面和桌面交互验证。确认原可见 QEMU 进程一直存在且未被替换、退出或重启。
